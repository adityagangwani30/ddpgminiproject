1. TITLE PAGE
=====================================================================

Project Title
DDPG Based Adaptive Transmit Power Control in a Single-Cell Wireless Network

Brief Description
This project implements a centralized uplink power-control framework where a
Deep Deterministic Policy Gradient (DDPG) agent learns continuous transmit
power allocation for multiple users in a single-cell wireless network. The
controller maximizes spectral efficiency while penalizing excess power usage,
thus learning a practical throughput-energy tradeoff under fading channels.

Tools Used
- Python
- Stable-Baselines3
- NumPy
- Matplotlib
- Gymnasium
- PyTorch
- Pandas (for result table export)

=====================================================================
2. INTRODUCTION
=====================================================================

Transmit-power control is a core wireless optimization problem. In the uplink,
simultaneous transmissions from multiple users create mutual interference. If
all users transmit at full power, interference can dominate and reduce overall
link quality and energy efficiency. If all users transmit conservatively,
interference decreases but throughput may be underutilized.

Therefore, the practical goal is to balance three competing dimensions:
1) aggregate throughput,
2) transmit-energy consumption,
3) service fairness across users.

Adaptive power control is necessary because wireless channels vary over time
due to fading and environment dynamics. A static heuristic cannot react to each
instantaneous channel realization, while an adaptive policy can exploit good
channels and avoid unnecessary power in poor channels.

Reinforcement learning is a suitable approach because the control space is
continuous, the environment is stochastic, and decision quality must be learned
from interaction rather than explicit closed-form labels.

3. SYSTEM MODEL
=====================================================================

3.1 Scenario
The system models one base station and K single-antenna uplink users. The
implementation constrains K to 3 <= K <= 5.

3.2 Channel Model
Per-user channel coefficients follow Rayleigh fading:

h_i ~ CN(0, 1)

Equivalent channel gain form:

g_i = |h_i|^2

In the code, gains are sampled directly from Exp(1), which is mathematically
equivalent to |h_i|^2 under h_i ~ CN(0,1).

3.3 SINR
For user i, the implemented uplink SINR is:

SINR_i = (P_i * g_i) / (sum_{j != i} P_j * g_j + sigma^2)

where:
- P_i is transmit power of user i,
- sigma^2 is AWGN noise power.

3.4 Spectral Efficiency
Per-user spectral efficiency is:

R_i = log2(1 + SINR_i)

System sum rate:

R_sum = sum_{i=1..K} R_i

3.5 Reward Function
The RL reward at time t is:

r_t = sum_{i=1..K} log2(1 + SINR_i,t) - lambda_power * sum_{i=1..K} P_i,t

Interpretation:
- First term encourages high throughput.
- Second term penalizes excessive transmit power.
- lambda_power controls the throughput-energy tradeoff.

3.6 Power Constraints
Each power component is bounded:

0 <= P_i <= P_max

The environment clips actions to this feasible interval every step.

3.7 Fairness Metric
Jain fairness index is used on per-user rates:

J = (sum_i R_i)^2 / (K * sum_i R_i^2)

Values close to 1 indicate balanced user rates.

=====================================================================
4. REINFORCEMENT LEARNING FORMULATION
=====================================================================

The power-control problem is formulated as a continuous-action MDP.

4.1 Agent
Centralized base-station controller.

4.2 State
s_t = [g_1,t, g_2,t, ..., g_K,t]

where g_i,t = |h_i,t|^2.

4.3 Action
a_t = [P_1,t, P_2,t, ..., P_K,t]

continuous and clipped to [0, P_max].

4.4 Reward
r_t = sum_i R_i,t - lambda_power * sum_i P_i,t

4.5 Transition
After each action and reward computation, a new channel vector is sampled.
Episodes terminate after fixed horizon `episode_length`.

=====================================================================
5. DDPG ALGORITHM EXPLANATION
=====================================================================

5.1 Motivation
DDPG is an off-policy actor-critic algorithm designed for continuous actions.
This makes it appropriate for vector-valued transmit-power control.

5.2 Actor Network
Approximates deterministic policy mu_theta(s) and outputs power actions.

5.3 Critic Network
Approximates Q_phi(s, a), evaluating expected return of state-action pairs.

5.4 Replay Buffer
Transitions (s, a, r, s') are stored and sampled uniformly to:
- break temporal correlations,
- improve sample reuse efficiency.

5.5 Target Networks
Target actor and target critic are updated by Polyak averaging:

theta_target <- tau * theta_online + (1 - tau) * theta_target

This stabilizes bootstrapped Q-learning updates.

5.6 Exploration
Gaussian action noise is added during training:

a_noisy = mu_theta(s) + epsilon, epsilon ~ N(0, sigma^2 I)

5.7 Update Principles
Critic target:

y = r + gamma * Q_target(s', mu_target(s'))

Critic loss:

L(phi) = E[(Q_phi(s, a) - y)^2]

Actor objective:

J(theta) = E[Q_phi(s, mu_theta(s))]

5.8 Training Loop (Implemented Behavior)
1) Observe state.
2) Predict action (with exploration noise during training).
3) Step environment and collect transition.
4) Store transition in replay buffer.
5) Perform critic/actor gradient updates.
6) Soft-update target networks.
7) Continue until total_timesteps.

6. CODE ARCHITECTURE EXPLANATION
=====================================================================

6.1 `config.py`
Purpose:
Centralized configuration and artifact path definitions.

Key content:
- Default environment parameters (`N_USERS`, `P_MAX`, `NOISE_POWER`,
  `LAMBDA_POWER`, `EPISODE_LENGTH`).
- Training/evaluation defaults (`TRAINING_TIMESTEPS`, `LEARNING_RATE`,
  `RANDOM_SEED`, `EVAL_STEPS`, `EVAL_RUNS`).
- Artifact file names and helper path functions (`results_path`, `legacy_path`).

6.2 `environment.py`
Purpose:
Custom Gymnasium environment implementing channel sampling, SINR/rate
calculation, reward generation, fairness metric, and action clipping.

Key functions/classes:
- `compute_sinr_rates(...)`
- `jain_fairness(...)`
- `UplinkPowerControlEnv` with `reset()` and `step()`

6.3 `baselines.py`
Purpose:
Non-learning baselines for reference comparison.

Implemented baselines:
- Equal power
- Fractional power control
- Greedy strongest-user rule

Key function:
- `evaluate_static_policy_on_channels(...)`

6.4 `train_ddpg.py`
Purpose:
Train DDPG using Stable-Baselines3 and save artifacts.

Key components:
- `TrainConfig` dataclass
- `train_ddpg(config)`
- `plot_training_rewards(...)`
- `quick_policy_report(...)`
- CLI parsing with overrides (`--users`, `--timesteps`, etc.)
- Logging-based runtime reporting

6.5 `evaluation.py`
Purpose:
Evaluate trained DDPG vs baselines on shared channel sequences.

Key features:
- Professional results table in terminal.
- Metrics: sum rate, total power, Jain fairness, power efficiency.
- Multi-run averaging (`--runs`) for robust reporting.
- CSV export (`evaluation_summary.csv`).
- Plot generation:
  - training_reward_vs_timesteps.png
  - sum_rate_comparison.png
  - power_usage_comparison.png
  - fairness_comparison.png
  - power_efficiency_comparison.png
  - user_rate_cdf.png

6.6 `demo.py`
Purpose:
Live inference visualization using a trained model.

Behavior:
- Loads model checkpoint.
- Runs deterministic inference in environment.
- Renders two real-time subplots:
  - top: channel gains
  - bottom: allocated powers
- Updates with `plt.pause(0.1)` (default configurable).

7.2 Training Convergence
The reward-vs-episode and reward-vs-timestep plots indicate whether policy
learning stabilizes. A rising moving-average trend followed by plateau is
typical of convergence to a stable operating policy.

7.3 Cross-Method Comparison
Evaluation compares DDPG against Equal/Fractional/Greedy baselines.
Interpretation dimensions:
- Sum rate: aggregate throughput.
- Total power: average transmission cost.
- Power efficiency: throughput per unit power.
- Fairness: user-rate balance (Jain index).

7.4 Typical Tradeoff Interpretation
- Greedy policies can produce very high sum rate but often poor fairness.
- Equal power is simple but can be power-inefficient.
- Fractional control may improve fairness but can reduce throughput.
- DDPG tends to learn a reward-aligned tradeoff between throughput and power.

7.5 Why Shared-Channel Evaluation Matters
All methods are tested on the same channel sequences, which removes random
channel luck and ensures differences are due to policy behavior.

=====================================================================
9. AUTOMATED RESULTS REPORTING PIPELINE
=====================================================================

9.1 Overview
After evaluation completes, the system automatically generates a professional
Results and Performance Analysis report in PDF format. This report is saved
as results/Results_Analysis_Report.pdf and provides a self-contained summary
of all evaluation outcomes with embedded plots and computed metric values.

This feature eliminates the need for manual report assembly: evaluation metrics,
comparison plots, and interpretive analysis are combined into a single document
that can be reviewed, submitted, or presented immediately after running
evaluation.py.

9.2 Pipeline Mechanism
The reporting pipeline (implemented in generate_results_report.py) operates in
the following stages:

Stage 1: Metric Collection
  After evaluation.py computes per-method metrics (sum rate, total power,
  Jain fairness index, power efficiency) averaged over multiple independent
  channel sequences, it passes the aggregated results dictionary and experiment
  configuration parameters to the report generator.

Stage 2: Plot Reference
  The report references all PNG plots already generated and saved to the
  results/ directory by evaluation.py. These include:
  - training_reward_vs_timesteps.png
  - sum_rate_comparison.png
  - power_usage_comparison.png
  - power_efficiency_comparison.png
  - fairness_comparison.png
  - user_rate_cdf.png (included conditionally if available)

Stage 3: PDF Construction
  The report generator builds the PDF programmatically using the fpdf2
  Python library. No external compilation tools are required. Each section
  embeds the relevant plot image and inserts computed metric values directly
  into the analysis text, producing accurate and reproducible prose.

Stage 4: Output
  The completed PDF is written to results/Results_Analysis_Report.pdf.

9.3 Report Contents
The generated report contains only results analysis. It does not restate
system model equations, algorithm derivations, or architectural descriptions
that are already covered in this documentation. The report includes:

  1) Title and Configuration Summary
     Project name, date, and key experiment parameters (number of users,
     noise power, power penalty coefficient, training timesteps, episode
     length).

  2) Training Convergence Analysis
     Interpretation of the training reward curve, discussion of convergence
     behavior and learning stability.

  3) Sum Rate Comparison
     Cross-method comparison of average sum rate with a metrics table and
     bar chart. Analysis of why DDPG outperforms or compares to baselines.

  4) Power Efficiency Analysis
     Discussion of transmit power usage and throughput-per-unit-power across
     methods. Explains the reward-power tradeoff learned by the agent.

  5) Fairness Analysis
     Jain Fairness Index results with interpretation of fairness-performance
     tradeoffs.

  6) CDF of User Rates (conditional)
     Empirical CDF of per-user spectral efficiency, interpreting rate
     distributions and disparity across methods.

  7) Final Observations
     Enumerated summary of key findings: sum-rate superiority, power
     efficiency, fairness tradeoff, and convergence confirmation.

9.4 Benefits for Reproducibility and Grading
  - All metric values in the report are computed and inserted programmatically,
    eliminating transcription errors.
  - The report is regenerated from scratch on every evaluation run, ensuring
    it always reflects the latest model and configuration.
  - Evaluators can verify results by re-running evaluation.py and comparing
    the regenerated report against the submitted version.
  - The PDF format provides a portable, printable artifact suitable for
    academic review and grading.
