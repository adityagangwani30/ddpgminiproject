# DDPG-Based Adaptive Transmit Power Control in a Single-Cell Wireless Network

This repository implements a mini project on adaptive uplink transmit power control using Deep Deterministic Policy Gradient (DDPG), with comparisons against classical baseline methods.

## 1. Project Goal

Build a centralized power controller at the base station that learns continuous user transmit powers to maximize spectral efficiency while penalizing power usage.

Reward used in training:

\[
\text{Reward} = \sum_i \log_2(1+\text{SINR}_i) - \lambda \sum_i P_i
\]

with

\[
\text{SINR}_i=\frac{P_i|h_i|^2}{\sum_{j\neq i} P_j|h_j|^2+\sigma^2}
\]

## 3. Folder Contents (What each file does)

- `environment.py`
  - Custom Gymnasium environment `UplinkPowerControlEnv`.
  - State is channel gains `[|h_1|^2, ..., |h_K|^2]`.
  - Action is continuous powers `[P_1, ..., P_K]` with `0 <= P_i <= P_max`.
  - Implements SINR, spectral efficiency, reward, reset, and step.
  - Includes utility functions `compute_sinr_rates()` and `jain_fairness()`.

- `baselines.py`
  - Implements baseline policies:
  - Equal power allocation.
  - Fractional power control.
  - Greedy SINR-style allocation.
  - Includes evaluation helper `evaluate_static_policy_on_channels()`.

- `train_ddpg.py`
  - Trains the DDPG agent using Stable-Baselines3.
  - Uses replay buffer, target networks (native DDPG), and normal action noise.
  - Supports training presets: `quick`, `fast`, `balanced`, `full`.
  - Saves trained model and training plots/files.

- `evaluation.py`
  - Loads trained DDPG model from `ddpg_power_control_model.zip`.
  - Evaluates DDPG and baselines on the same random channel sequence.
  - Computes average sum-rate, average power, Jain fairness, and power efficiency.
  - Generates comparison plots.

- `requirements.txt`
  - Python dependency list used for local setup and Colab setup.

- `run_on_colab.ipynb`
  - End-to-end Google Colab notebook.
  - Clones this repository, installs dependencies, trains model, evaluates baselines, and shows plots.

- `ddpg_power_control_model.zip`
  - Saved trained model file (generated by `train_ddpg.py`).

- `training_episode_rewards.npy`
  - Numpy array of episode rewards (generated by `train_ddpg.py`).

- `training_reward_curve.png`
  - Training convergence plot (episode reward vs episodes).

- `sum_rate_comparison.png`
  - Bar chart of average sum-rate across methods.

- `power_efficiency_comparison.png`
  - Bar chart of power efficiency across methods.


## 4. System Model Summary

- Single-cell uplink.
- Single base station.
- `K` users (`K` between 3 and 5, default 4).
- Single antenna per node.
- Time-varying channels: new fading sample every time step.
- AWGN noise with configurable power.

Notes:
- During training, channel gain is sampled efficiently from an exponential distribution (`|h|^2 ~ Exp(1)`), which is equivalent to `h ~ CN(0,1)`.
- During evaluation, gains are generated from explicit complex Gaussian samples.

## 5. Baseline Methods Included

- Equal Power Allocation.
- Fractional Power Control (`alpha=0.5` default).
- Greedy SINR-based allocation (strongest-user-first rule).

## 7. How to Run (From Clone to Output)

### Step 1: Clone repository

```bash
git clone <your-repo-url>
cd <your-repo-folder>
```

### Step 2: Create and activate virtual environment

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
python -m venv .venv
source .venv/bin/activate
```

### Step 3: Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### Step 4: Train the DDPG agent

Recommended: use the same virtual-environment interpreter explicitly to avoid package mismatch.

Windows PowerShell commands:

```powershell
# Quick sanity run (very fast)
.venv\Scripts\python.exe train_ddpg.py --mode quick

# Fast mode (alias of quick preset)
.venv\Scripts\python.exe train_ddpg.py --mode fast

# Balanced mode (default; good speed vs quality)
.venv\Scripts\python.exe train_ddpg.py --mode balanced

# Full experiment run (50,000 timesteps)
.venv\Scripts\python.exe train_ddpg.py --mode full

# Full run with explicit settings
.venv\Scripts\python.exe train_ddpg.py --mode full --timesteps 50000 --device cpu --cpu-threads 1

# Optional GPU run (if CUDA is available)
.venv\Scripts\python.exe train_ddpg.py --mode full --device cuda
```

Linux/macOS equivalents (after activation):

```bash
python train_ddpg.py --mode quick
python train_ddpg.py --mode fast
python train_ddpg.py --mode balanced
python train_ddpg.py --mode full
```

Debug/very short check:

```bash
python train_ddpg.py --mode quick --timesteps 1000 --skip-report
```

Optional useful flags:

- `--timesteps <int>` override timesteps.
- `--device cpu|cuda|auto` select compute device.
- `--cpu-threads <int>` set PyTorch CPU thread count.
- `--skip-report` skip final quick performance report.

Example:

```bash
python train_ddpg.py --mode full --device cpu --cpu-threads 1
```

### Step 5: Evaluate DDPG vs baselines

Windows PowerShell:


## 9. Reproducibility Notes

- Fixed seeds are set in scripts for consistent experiments.
- If results differ, confirm:
- You are using the same Python environment.
- Package versions are consistent.
- Training mode and timesteps are the same.

## 10. Common Issues and Fixes

- `ModuleNotFoundError: stable_baselines3`
  - Install packages in the same Python interpreter used to run scripts.
  - Example: `.venv\Scripts\python.exe -m pip install stable-baselines3 gymnasium shimmy`

- `PermissionError` while loading model path without `.zip`
  - Ensure evaluation loads `ddpg_power_control_model.zip` exactly.

- Slow training
  - Use `--mode quick` or `--mode balanced`.
  - Use `--cpu-threads 1` for small models on CPU.
  - Use `--skip-report` to reduce post-training time.

## 11. Suggested Workflow

1. Run `quick` mode to verify pipeline end-to-end.
2. Run `balanced` mode for better policy quality.
3. Run `full` mode for final report results.
4. Run `evaluation.py` and include generated plots in your mini project report.
